# 매핑 센서 경로 검증 — 2026-09-09

이 문서는 센서 시간/TF 검사와 사용자가 허용한 실제 저속 주행 시험을 기록한다. IMU 장착 방향 검증은 아직 완료되지 않았다. 모터 명령의 방향만으로 IMU 방향을 판정하지 않는다.

## 확인된 경로

| 경로 | 확인 결과 | 남은 한계 |
|---|---|---|
| CAN → JointState | MIT 위치 피드백을 해석하고 방향 부호를 적용한다. 모터 명령 적분이 아니다. | MIT 위치가 감속기 입력/출력 중 어느 축의 각도인지 실측 확인 필요. CAN 커널 수신 타임스탬프를 쓰지 않고 파싱 시각으로 freshness를 계산한다. |
| JointState → odom → TF | JointState header.stamp를 유지한다. 거리 단위 m, 각도 rad. 바퀴 위치 변화로 원호 적분한다. | 엔코더 각도와 실제 지면 이동이 일치하는지는 별개다. 현재 시험에서 큰 차이가 관측됐다. |
| odom 배율 | 시험 스택은 1.0. 거리·회전 모두 적용되며 명령 속도는 바꾸지 않는다. | 단일 배율로 슬립/정지마찰/기계적 유격을 해결할 수 있다고 검증되지 않았다. |
| 라이다 SDK → LaserScan | 호스트 grabScanDataHq 호출 직전 시각을 header에 사용. 함수 대기 시간을 scan_time 및 time_increment에 사용. | SDK가 제공하는 스캔 시작 추정 시각을 버린다. SDK는 CLOCK_MONOTONIC이며 ROS 시스템 시각으로 직접 대입하면 안 된다. |
| 라이다 점별 시간 | 각도 정렬·보간 후 기본 inverted=false에서 배열을 역순 발행하고 time_increment는 양수. | 원시 측정 순서와 발행 순서의 시간 일치 여부를 실기 계측해야 한다. 의심 지점이며 원인 확정이나 수정 완료가 아니다. |
| Cartographer | 현재 /scan과 /odom 구독. map→odom 발행은 단독. | 측정 시각이 잘못 붙은 데이터의 물리적 지연은 TF 존재 검사로 알 수 없다. |
| IMU 시리얼 → ROS | CSV 9개 값. 가속도 g→m/s², 자이로 deg/s→rad/s. 시리얼 읽기 후 호스트 시각 사용. orientation_covariance[0]=-1. | MCU 측정 시각/시퀀스가 없다. 펌웨어에서의 실제 단위·축 정의는 소스 확인되지 않음. 자세 quaternion은 유효하지 않다. |
| IMU → SLAM | 현재 IMU 미사용. /imu/mapping 발행 없음. base_link→imu_link TF 없음. | 장착 회전·위치 검증 전 verified:false 유지. 정지 중력만으로 전방축/yaw를 확정할 수 없다. |
| 기존 몸체 제어 | body_pitch_node는 atan2(ay,-az), -gx 사용. | 이 관례가 실제 장착과 맞는지 별도의 알려진 pitch 동작 필요. raw IMU 전역 부호를 임의 변경하지 않았다. |
